# 充电会话状态机详细设计文档

## 1. 设计目标

- 支持电动汽车充电全流程的状态管理，覆盖预约、进场、充电、支付、完成等业务环节。
- 状态转换规则集中管理，便于维护和扩展。
- 采用领域事件驱动副作用，解耦核心业务与外围逻辑。
- 聚合根封装业务规则，保证一致性与并发安全。
- 充分利用 Java 21（record/sealed interface）和 Spring Boot 3（事件、JPA、事务）生态。

## 3. 状态转换表

- 采用静态 Map 实现，集中管理所有状态流转规则。
- 支持后续扩展为配置驱动或数据库驱动。

```java
public class TransitionTable {
    private static final Map<ChargeSessionStatus, Map<ChargeSessionEvent, ChargeSessionStatus>> TABLE = Map.of(
        ChargeSessionStatus.INIT, Map.of(
            ChargeSessionEvent.RESERVE_CMD_SUCCESS, ChargeSessionStatus.RESERVED,
            ChargeSessionEvent.PLUG_DETECTED, ChargeSessionStatus.READY_TO_CHARGE
        ),
        ChargeSessionStatus.RESERVED, Map.of(
            ChargeSessionEvent.LOCK_READY, ChargeSessionStatus.LOCK_READY,
            ChargeSessionEvent.PLUG_DETECTED, ChargeSessionStatus.READY_TO_CHARGE,
            ChargeSessionEvent.RESERVATION_TIMEOUT, ChargeSessionStatus.END,
            ChargeSessionEvent.CANCEL_RESERVATION, ChargeSessionStatus.END
        ),
        // ... 其他状态转换，详见业务流程
        ChargeSessionStatus.READY_TO_CHARGE, Map.of(
            ChargeSessionEvent.START_REQUESTED, ChargeSessionStatus.CHARGE_STARTING,
            ChargeSessionEvent.UNPLUG_DETECTED, ChargeSessionStatus.INIT
        )
        // ...补全所有业务流转
    );

    public static Optional<ChargeSessionStatus> getNext(ChargeSessionStatus current, ChargeSessionEvent event) {
        return Optional.ofNullable(TABLE.getOrDefault(current, Map.of()).get(event));
    }
}
```

## 5. 聚合根与状态机核心

### 5.1 ChargeSession 聚合根

```java
@Entity
public class ChargeSession extends AbstractAggregateRoot<ChargeSession> {
    @Id
    private Long id;
    @Enumerated(EnumType.STRING)
    private ChargeSessionStatus status;
    @Version
    private Long version;
    // 其他业务字段...

    public void handleEvent(ChargeSessionEvent event, Object... context) {
        ChargeSessionStatus next = TransitionTable.getNext(this.status, event)
            .orElseThrow(() -> new IllegalStateException("非法状态转换: " + this.status + " + " + event));
        this.status = next;
        this.registerEvent(new ChargeSessionStatusChangedEvent(this.id, this.status, event, Instant.now()));
    }
}
```

- 封装所有业务规则，保证一致性。
- 通过 `@Version` 实现乐观锁，防止并发冲突。
- 通过 `registerEvent` 注册领域事件，Spring Data 自动发布。

## 6. 应用服务与事件监听

### 6.1 应用服务

```java
@Service
public class ChargeSessionService {
    @Autowired
    private ChargeSessionRepository repository;

    @Transactional
    public void processCommand(Long sessionId, ChargeSessionEvent event, Object... context) {
        ChargeSession session = repository.findById(sessionId)
            .orElseThrow(() -> new NotFoundException("会话不存在"));
        session.handleEvent(event, context);
        repository.save(session); // 触发事件发布
    }
}
```

### 6.2 事件监听器

```java
@Component
public class ChargeSessionEventListener {
    @EventListener
    public void onStatusChanged(ChargeSessionStatusChangedEvent event) {
        // 处理副作用，如调用外部服务、推送通知等
    }
}
```

- 可用 `@TransactionalEventListener` 控制事务钩子（如 AFTER_COMMIT）。

## 7. 状态机与业务流程映射

- 结合 flowchart.md 和 user_stories.yml，补全所有状态与事件流转。
- 典型流程如：预约成功（INIT→RESERVED）、插枪（RESERVED→READY_TO_CHARGE）、启动充电（READY_TO_CHARGE→CHARGE_STARTING→CHARGING）、停止充电、支付、结束等。

## 8. 并发控制与持久化

- JPA `@Version` 字段实现乐观锁，防止并发冲突。
- 所有状态变更均持久化，保证一致性。
- 领域事件与事务生命周期绑定，保证副作用与主业务一致性。

## 9. 可扩展性与维护建议

- 新增状态/事件：只需扩展枚举和 TransitionTable。
- 新增副作用：只需添加新的事件监听器。
- 业务规则变更：集中在聚合根和状态表，易于维护。
- 支持分布式一致性（可扩展 Outbox Pattern）。

## 11. 典型用例流程（示意）

1. 用户预约充电桩 → Controller → Service → 聚合根 handleEvent(RESERVE_CMD_SUCCESS) → 状态变更为 RESERVED → 发布事件
2. 用户插枪 → handleEvent(PLUG_DETECTED) → 状态变更为 READY_TO_CHARGE
3. 用户启动充电 → handleEvent(START_REQUESTED) → 状态变更为 CHARGE_STARTING
4. 充电桩确认 → handleEvent(START_CONFIRMED) → 状态变更为 CHARGING
5. 用户/系统停止充电 → handleEvent(STOP_REQUESTED/STOP_CONFIRMED) → 状态变更为 CHARGE_STOPPED
6. 用户支付 → handleEvent(PAYMENT_CONFIRMED) → 状态变更为 PAID
7. 结束 → handleEvent(UNPLUG_DETECTED/END) → 状态变更为 END
